# Nota di sviluppo — 20 maggio 2026

Riepilogo dello stato a fine giornata, per riprendere domani.

## Cosa è stato fatto oggi

### 1. Sblocca contatto + invio preventivo (idraulico)
- Sistemato il flusso "Sblocca contatto" → apertura diretta della chat / invio preventivo.
- Rinominato il CTA da **"Sblocca subito"** a **"Invia preventivo"**.
- File toccati: `src/components/dashboard/TrialRequestCard.tsx`, `src/pages/RequestsPage.tsx`.

### 2. Preferenza di contatto del cliente (telefono sì/no)
- Aggiunto checkbox nel wizard cliente: **"Non desidero essere contattato telefonicamente"** (default: deflaggato → telefono OK).
- Se il cliente flagga: il numero di telefono **non** viene mostrato all'idraulico e nella notifica email/WhatsApp compare "Contatto solo tramite email".
- Altrimenti: viene mostrato anche il telefono ("Contatto anche telefonicamente").
- Sconto applicato sul costo di sblocco quando è **chat-only**: **−30%**.
- File toccati: `src/components/InlineWizard.tsx`, `src/components/dashboard/TrialRequestCard.tsx`, `src/hooks/useTrialRequests.ts`, `src/pages/RequestPage.tsx`, `supabase/functions/notify-plumbers/index.ts`.
- Migrazioni: `20260520105858_*.sql`, `20260520110205_*.sql` (colonna preferenza contatto + logica prezzo).

### 3. Separazione ruoli cliente / idraulico (bug "saldo insufficiente" su account cliente)
Problema: loggandosi come `prova1@gmail.com` (cliente) l'app trattava l'utente come idraulico (mostrava "Saldo insufficiente" e 0 conversazioni).

Interventi:
- `Header.tsx`: ora usa `usePlumberProfile` → se c'è profilo idraulico mostra "Dashboard" → `/dashboard`; altrimenti mostra "Le mie richieste" → `/account`.
- Nuovo componente `DashboardRedirect.tsx` per smistare `/dashboard` in base al ruolo.
- `App.tsx`: `/dashboard` ora usa `<DashboardRedirect />` invece di redirect statico.
- `DashboardLayout.tsx`: guard che reindirizza a `/account` se l'utente non è idraulico.
- `usePlumberProfile.ts`: aggiunti `hasFetched` e `fetchedUserId` per evitare profili "stale" dopo logout/login.
- `ClientAccountPage.tsx`: riscritta con verifica ruolo, query conversazioni con anteprima ultimo messaggio, nome idraulico, ordinamento per `last_message_at`.
- Migrazione `20260520112121_*.sql`: aggiornate **RLS policy** su `service_requests`, `conversations`, `conversation_messages` per consentire accesso al cliente anche tramite **email JWT** (oltre che `client_user_id`), risolvendo i casi in cui `client_user_id` non è popolato.
- `RequestsPage.tsx` e `PreventiviPage.tsx`: query allineate al nuovo schema RLS.
